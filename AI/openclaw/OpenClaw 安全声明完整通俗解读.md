# OpenClaw 安全声明完整通俗解读
这份不是普通提示，是**项目官方风险告知**，核心一句话：
OpenClaw 是测试阶段业余项目，自带文件读取、工具执行权限，**默认安全边界极弱，乱部署极易泄密、越权操作、多用户互相越权**，必须手动做全套加固才能安全使用。

## 一、基础风险总览（分段拆解）
### 1. 项目定位风险
> OpenClaw是一个业余项目，目前仍处于测试阶段。
- 无专业安全团队审计，存在未知漏洞、逻辑缺陷，不要用于企业核心业务、涉密场景；
- 功能不完善，安全机制是半成品，很多防护需要用户自己手动配置。

### 2. 默认权限极高，天然危险
> 默认情况下，OpenClaw是一个个人代理：一个受信任的操作员边界。此机器人可以读取文件，并在启用工具时执行操作。一个错误的提示可能会诱使它做出不安全的行为。
1. **文件读取权限**：程序能直接读取运行主机上的本地文件（配置、密钥、隐私文档）；
2. **工具执行权限**：开启工具后可调用系统命令、操作本地程序、读写磁盘、发起网络请求；
3. **提示注入风险**：别人构造恶意对话提示词，就能诱导机器人读取敏感文件、删改数据、泄露密钥。
4. 设计初衷是**单人自用**，默认完全信任和它对话的人。

### 3. 致命缺陷：不支持多用户隔离（最重点）
> OpenClaw默认情况下并非具有敌意的多租户边界。如果多个用户可以向一个启用了工具的代理发送消息，那么他们共享该委托工具权威。
- 多租户 = 多人共用同一个机器人；
- 默认无权限隔离：A用户发消息，能诱导工具读取B用户的文件、操作B的数据；所有人共用一套系统权限，没有分隔；
- 场景举例：同时对接QQ、钉钉、企业微信多渠道，陌生人私聊也能调用高危工具，跨渠道窃取信息。

### 4. 免责警告
> 如果你对安全加固和访问控制不熟悉，就不要运行OpenClaw。在启用工具或将其暴露给互联网之前，请向有经验的人寻求帮助。
直白翻译：
如果你看不懂白名单、沙盒、权限隔离这些概念，直接别用；
一旦把机器人公网暴露、开启工具执行，出事后果自己承担，项目不兜底。

## 二、推荐基线：官方强制安全加固方案（逐条解释用途）
### 1. 配对码+联系人白名单（对应你第一条日志的 `plugins.allow`）
- 配对码：设备/用户绑定校验，陌生人无法直接连接机器人；
- 白名单门控：只允许你信任的账号、好友触发机器人功能，拦截外部陌生人。
- 对应你之前的警告日志：`plugins.allow` 插件白名单是空，就是缺少这层防护。

### 2. 多人共用场景：物理级隔离（最高安全标准）
> 多用户/共享收件箱：分离信任边界，最好独立系统用户/独立主机
多人同时使用机器人时，**不要共用一套OpenClaw实例**：
- 轻度：分开配置、分开凭证；
- 重度安全：每个渠道/每个用户单独一台虚拟机、单独系统账号，彻底隔绝文件与工具权限。

### 3. 沙盒 + 最小权限工具
- 沙盒：限制工具运行环境，就算被恶意诱导，也无法访问主机全局文件、无法执行高危系统命令；
- 最小权限：只开启你真正需要的工具（比如只允许读取日志，禁止删除文件、执行shell），多余工具全部关闭。

### 4. 私聊会话隔离
`session.dmScope: per-channel-peer`
不同私聊好友、不同渠道的对话数据完全隔离，A的私聊指令不能影响B的会话，防止跨用户数据泄露。

### 5. 敏感文件隔离
机器人运行目录、可读目录里，**绝对不能存放密钥、密码、合同、隐私数据、数据库凭证**；
一旦被提示注入，文件内容会被直接发送给攻击者。

### 6. 高危场景使用强模型
若机器人对外开放、允许陌生人对话，必须使用高安全能力大模型；低阶模型更容易被提示词劫持，执行危险操作。

## 三、内置安全审计命令
```bash
openclaw 安全审计 --深度
openclaw 安全审计 --修复
```
1. `--深度`：扫描当前配置所有安全漏洞：空白名单、无会话隔离、工具权限过大、敏感文件可读、未开启配对校验等，输出风险清单；
2. `--修复`：自动补全基础安全配置（填充插件白名单、开启会话隔离、禁用高危工具等），一键消除低危警告。

## 四、官方安全文档
`https://docs.openclaw.ai/gateway/security`
所有权限配置、白名单、沙盒、多用户隔离、公网部署防护的完整教程，所有生产/对外部署前必读。

# 三、极简总结（分使用场景对照）
## 场景1：仅本地单人自用，不对外暴露、不加任何机器人渠道
风险低，但仍建议：
1. 执行安全审计修复；
2. 运行目录不放密码/密钥；
3. 非必要不开启文件读写、系统执行工具。

## 场景2：对接QQ/钉钉/企业微信等，允许多人私聊使用（你当前场景）
属于高风险，必须全部做完加固基线：
1. 配置 `plugins.allow` 插件白名单、开启配对码校验；
2. 开启私聊会话隔离；
3. 限制工具最小权限，开启沙盒；
4. 不要存放任何机密文件在程序可访问目录；
5. 定期运行安全审计扫描漏洞。

## 场景3：公网部署、外网陌生人可访问
不建议使用；若必须用，需要多主机隔离、严格白名单、完整沙盒，且找专业运维人员配置。

## 核心底线
OpenClaw默认是“完全信任所有对话者”的单人工具，**所有多用户、对外使用的安全能力都需要用户手动配置，不加固就存在信息泄露、主机被操控风险**。
