# 相机到 SoC 的数据通路

> 类型：concept
> 一句话：从车载相机到 DDR 内存的全链路：AHD/LVDS -> 解串/解码 -> MIPI -> VI/DMA -> DDR

## 是什么

一张车载图像从相机镜头最终进入 DDR 内存，要经过四个环节：**外部传输 -> 板级协议转换 -> SoC 内部硬件流水线 -> DMA 搬运**。

### 外部接口（成品相机级）

| 接口 | 物理介质 | 特点 | 典型场景 |
| --- | --- | --- | --- |
| AHD（模拟高清） | 同轴线 | 模拟波形，成本低，传 300~500 米 | 传统环视、安防改造 |
| LVDS / SerDes（GMSL、FPD-Link） | 同轴线 + PoC 供电 | 串行器把视频/时钟/I2C/供电打包，抗干扰强、无压缩零延迟，传 10~15 米 | 智驾域控外部接入主流 |
| IPC（网络摄像机） | 网线 | 相机内部压缩编码，自带算力，但百毫秒级延迟 | 安防、低延迟要求不高的场景 |

### 板级内部：MIPI CSI-2

MIPI CSI-2 是芯片间通信协议（不是芯片、也不是像素格式），物理形态是 PCB 走线、FPC 排线或 BTB 连接器。引脚少、带宽高、支持虚拟通道多路复用、低功耗，是 99% 视觉 SoC 接收高清视频的统一内部入口。

### SoC 内部流水线

```
外部相机 --> 解串/解码芯片 --> MIPI CSI-2 --> MIPI 控制器 --> VI 模块 --> DMA --> DDR
```

- **MIPI 控制器**：物理层电平接收 + 协议拆包，剥离包头后通过片内点对点专线把像素流递给 VI。
- **VI（视频输入模块）**：分离多路虚拟通道、校验行场同步、裁剪画面，像素暂存内部 FIFO，再由内置 DMA 搬运到内存。
- **CPU** 不参与像素搬运，只在启动时配置寄存器。

## 为什么

### 为什么外部信号必须转成 MIPI

主控 SoC 是纯数字芯片，MIPI 只支持十几厘米板级短传。长线信号进主板后必须"翻译"：

- 模拟转数字：AHD 相机 -> 解码芯片（如 XS9915B）-> MIPI CSI-2 -> SoC
- 长线数字转板级数字：LVDS 相机 -> 解串器（如 MAX96712）-> MIPI CSI-2 -> SoC

### 为什么用 DMA 而不是 CPU 搬数据

- **PIO 模式（无 DMA）**：VI 收到数据进 FIFO 后触发中断，CPU 亲自读寄存器再写 DDR，高速视频流瞬间耗尽 CPU。
- **DMA 模式**：CPU 启动时向 VI 控制寄存器写入目标地址，之后 VI 内置 DMA 引擎直接接管总线，把像素批量灌入 DDR 保留内存（CMA / MMZ），全程不经过 CPU 寄存器。

### 为什么多 DMA 并发不会互相堵死

现代 SoC 用 AXI Crossbar / NoC 总线矩阵，无路径冲突的读写并行；传输切成微秒级突发包（Burst），CPU 有 L1/L2 Cache 兜底。当 VI、NPU、VENC 同时抢 DDR 通道时，硬件仲裁器（Arbiter）用三种机制裁决：

- **QoS 优先级**：防丢帧的 VI、防黑屏的 VO 优先级最高
- **加权轮询**：分配时间片配额，防低优先级模块饿死
- **读写通道物理分离**

### 片上外设 vs 片外外设的控制差异

CPU 通过 MMIO（内存映射 IO）统一编址控制硬件：

- **片上外设**（VI、MIPI 控制器、片上 I2C）：直接挂在片内总线上，CPU 读写内存映射地址即可控制。
- **片外外设**（XS9915B 解码芯片）：不在片内地址空间，必须两步接力--CPU 先写片上 I2C 控制器寄存器，再由 I2C 控制器驱动外部引脚发脉冲，间接修改外部芯片寄存器。

对比 PC 架构：嵌入式 SoC 地址表出厂写死；PC 靠 BIOS/UEFI 开机自检时动态扫描内存和 PCIe BAR，热插拔设备动态分配地址。

## 例子

全景数据与控制链路：

```text
[AHD/LVDS 相机] --(同轴长线)--> [XS9915B / 解串器] --(MIPI CSI-2)--+
                                     ^                            |
                    (I2C 间接配置)    |                            v
                                     |                  [MIPI 控制器 拆协议包]
[CPU 核心] --(MMIO 直写)--> [片上 I2C 控制器]                      |
     |                                                          硬件专线
     |                                                             v
     +--(MMIO 配置 DMA 目标地址)----------------------------> [VI 模块 进 FIFO]
                                                                   |
                                                                   v (VI DMA)
                                                        [AXI 总线矩阵 + Arbiter]
                                                                   |
                                                                   v (QoS 优先)
                                                        [DDR 保留内存 环形缓冲区]
                                                                   |
                                                                   v
                                                     [ISP / IVPS / NPU / VENC]
```

## 坑

- **MIPI CSI-2 是协议不是格式**：RAW8/RAW10/RAW16/YUV422 才是像素格式。把 MIPI 当成"一种图像格式"会在解析时混淆 lane 数和数据类型。
- **虚拟通道（Virtual Channel）要显式分离**：一根 MIPI 线复用多路相机时，VI 模块按 VC ID 分流。不配置 VC 过滤，多路画面会叠在同一帧里。
- **DMA 目标内存必须是 CMA/MMZ 保留区**：普通 malloc 的内存在运行期可能被换出或碎片化，VI DMA 写不进去。驱动要 reserved-memory 节点留一块连续物理内存。
- **FIFO 溢出 = 丢帧**：VI FIFO 深度有限，总线仲裁失败或 DDR 带宽打满时 FIFO 溢出，表现为偶发丢帧但 CPU 不报错。排查要看 VI 中断状态寄存器的 FIFO overflow 位。
- **I2C 间接配置外部芯片要等就绪**：解串器/解码器上电后需要几毫秒才能响应 I2C，太早写寄存器会静默失败。驱动里要加 sleep 或 polling 中断引脚。
- **PoC 供电和同轴信号共线**：GMSL/FPD-Link 用同一根同轴线传视频和供电，电源设计不好会引入噪声导致 MIPI 误码，排查时要先量同轴线的纹波。
