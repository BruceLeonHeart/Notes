在 Linux 中，“端口可用”通常指**该端口当前没有被任何进程占用（空闲）**。最直接的做法是列出当前所有已被监听（占用）的端口，未出现在列表中的端口即为可用（空闲）端口。

### 1. 查看所有已占用的端口（推荐）

使用现代 Linux 标配的 `ss` 命令，执行速度快且信息完整：

```bash
sudo ss -tulnp

```

* **参数说明**：
* `-t`：显示 TCP 端口
* `-u`：显示 UDP 端口
* `-l`：仅显示处于监听（LISTEN）状态的端口
* `-n`：以数字形式显示端口号（不解析为服务名，速度更快）
* `-p`：显示占用该端口的进程名和 PID（需 `sudo` 权限才能看全）



**输出解读**：在 `Local Address:Port` 一列中看到的端口号（如 `0.0.0.0:80` 或 `127.0.0.1:3306`）都是**已被占用**的，避开这些端口即可。

---

### 2. 检查指定端口是否可用

如果你已经选定了一个特定端口（例如 `8080`），可以直接过滤查看它是否被占用：

```bash
# 方法 A：使用 ss（推荐）
sudo ss -tulnp | grep :8080

# 方法 B：使用 lsof
sudo lsof -i :8080

```

* **判断标准**：如果命令运行后**没有任何输出**，说明 `8080` 端口当前未被本地进程占用，可以直接使用。

---

### 3. 自动获取一个随机可用端口

在编写自动化脚本时，如果需要系统直接分配一个空闲端口，可以通过 Python 快速获取：

```bash
python3 -c 'import socket; s=socket.socket(); s.bind(("", 0)); print(s.getsockname()[1]); s.close()'

```

---

### 4. 注意事项（外部访问与系统限制）

本地端口空闲并不代表外部网络一定能连上，部署服务时还需注意两点：

1. **避开系统保留端口与临时端口段**：
* **1 – 1023**：系统特权端口，普通用户无权绑定，且容易与常见服务（如 22、80、443）冲突。
* **32768 – 60999**：Linux 默认的客户端临时端口范围（`ip_local_port_range`），尽量避免将长期运行的服务绑定在此区间。
* **推荐选择**：建议优先使用 **1024 – 32767** 之间的未占用端口（如 `8080`、`8888`、`9000`）。


2. **检查防火墙是否放行**：
* 如果服务需要对外网或局域网提供访问，除了端口空闲外，还需确认本地防火墙（如 `ufw`、`firewalld`）以及云服务器厂商的**安全组**已放行对应端口。

不同 Linux 发行版默认使用的防火墙工具不同：**Ubuntu / Debian** 系通常使用 `ufw`，而 **CentOS / RHEL / Rocky / AlmaLinux / Fedora** 系通常使用 `firewalld`。以下按工具分别列出查看放行端口的方法。

#### 1. 使用 UFW（Ubuntu / Debian 系列）

执行以下命令查看防火墙当前状态及所有放行规则：

```bash
sudo ufw status numbered

```

* **输出解读**：
* 如果显示 `Status: inactive`，说明本地防火墙未开启，所有端口在本地均未受限制。
* 如果显示 `Status: active`，下方表格中 `Action` 为 `ALLOW` 的行即为已放行的端口（例如 `22/tcp ALLOW Anywhere` 表示 22 端口已对所有来源放行）。`numbered` 参数会同时显示规则编号，方便后续按编号管理。



---

#### 2. 使用 Firewalld（RHEL / CentOS / Rocky / Fedora 系列）

首先确认防火墙是否处于运行状态，然后列出默认区域（Zone）的所有放行配置：

```bash
# 1. 检查运行状态（返回 running 表示已开启）
sudo firewall-cmd --state

# 2. 查看当前生效区域（通常是 public）的所有放行规则
sudo firewall-cmd --list-all

```

* **输出解读**：
* **`ports:`** 直接显示手动放行的端口号和协议（如 `8080/tcp 9000/udp`）。
* **`services:`** 显示通过服务名放行的端口（如 `ssh` 对应 22 端口，`http` 对应 80 端口，`https` 对应 443 端口）。若要查看某个服务名具体对应哪个端口，可执行 `sudo firewall-cmd --info-service=http`。
* **多区域补充**：如果服务器配置了多个网络区域，可使用 `sudo firewall-cmd --list-all-zones` 查看全部区域的规则。



---

#### 3. 底层兜底方案（iptables / nftables）

如果以上两个命令均提示 `command not found`，或规则中看不到预期端口（例如 Docker 容器会自动绕过 ufw/firewalld 直接修改底层规则），可以直接检查内核级防火墙规则：

```bash
# 查看 nftables 规则（现代 Linux 默认底层）
sudo nft list ruleset

# 或查看传统 iptables 放行规则
sudo iptables -L -n -v

```

---

#### 4. 关键排查提示：云服务器安全组

如果你使用的是**阿里云、腾讯云、AWS、GCP** 等云服务器，操作系统内部的防火墙放行只是第一关。如果本地确认已放行但外部依然无法连接，必须登录云厂商控制台，检查实例关联的安全组（Security Group）入方向（Inbound）规则是否也放行了对应端口。
