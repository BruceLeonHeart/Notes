# 零拷贝 (Zero-Copy) 技术详解

> 类型：concept
> 一句话：零拷贝技术（mmap / sendfile / splice）


## 1. 什么是零拷贝？

零拷贝 (Zero-Copy) 是一种 I/O 操作优化的思想。在计算机执行 I/O 操作时，其核心目标是**尽量减少或完全避免 CPU 将数据在内核空间 (Kernel Space) 和用户空间 (User Space) 之间进行不必要的复制**。

**核心目的**：
-   **降低 CPU 开销**：数据拷贝是一项消耗 CPU 资源的操作。减少拷贝次数可以直接降低 CPU 使用率。
-   **减少内存带宽占用**：频繁在内存中移动数据会占用宝贵的内存带宽。
-   **减少上下文切换**：某些零拷贝技术可以减少内核态和用户态之间的切换次数，进一步提升性能。

零拷贝技术并非完全没有数据拷贝，而是指**没有 CPU 参与的数据拷贝**。数据在不同介质（如磁盘、网卡）之间的传输仍然依赖于 DMA (Direct Memory Access) 控制器进行拷贝。

---

## 2. 传统的数据传输方式 (非零拷贝)

以一个常见的场景为例：从文件中读取数据，并通过网络发送出去（例如一个 Web 服务器返回一个静态文件）。

传统的 `read` 和 `write` 操作流程如下：

**传统数据拷贝示意（read + write 流程）**

1.  **第1次拷贝 (DMA)**：`read` 系统调用触发 DMA 控制器将数据从**磁盘**拷贝到**内核空间的读缓冲区 (Read Buffer)**。
2.  **第2次拷贝 (CPU)**：CPU 将数据从**内核空间的读缓冲区**拷贝到**用户空间的应用程序缓冲区 (User Buffer)**。`read` 调用返回。
3.  **第3次拷贝 (CPU)**：`write` 系统调用导致 CPU 将数据从**用户空间的应用程序缓冲区**拷贝到**内核空间的套接字缓冲区 (Socket Buffer)**。
4.  **第4次拷贝 (DMA)**：DMA 控制器将数据从**内核空间的套接字缓冲区**异步地拷贝到**网络接口卡 (NIC)** 的缓冲区，最终通过网络发送。

**整个过程的开销**：
-   **4 次数据拷贝**：2 次 DMA 拷贝 + 2 次 CPU 拷贝。
-   **4 次上下文切换**：2 次 `read` 引起的切换 + 2 次 `write` 引起的切换。

其中，第2次和第3次 CPU 拷贝并没有对数据进行任何加工，是纯粹的搬运动作，构成了主要的性能瓶颈。

## 3. 实现零拷贝的主流技术

### A. `mmap` + `write`

`mmap` (Memory-mapped File) 是一种将文件或设备映射到内存的系统调用。它通过在用户空间和内核空间共享同一个缓冲区来减少一次 CPU 拷贝。

**工作流程**：
1.  应用程序调用 `mmap`，DMA 将数据从**磁盘**拷贝到**内核缓冲区**。
2.  `mmap` 调用并不将数据拷贝到用户空间，而是将**内核缓冲区**的地址与**用户空间**共享。这样，CPU 就不需要再进行一次内核到用户的拷贝。
3.  应用程序调用 `write`，CPU 将数据从**内核缓冲区 (现在也共享给了用户空间)** 拷贝到**内核套接字缓冲区**。
4.  DMA 将数据从**内核套接字缓冲区**拷贝到**网卡**。

**开销**：
-   **3 次数据拷贝**：2 次 DMA 拷贝 + 1 次 CPU 拷贝。
-   **4 次上下文切换**。

`mmap` 减少了一次 CPU 拷贝，但仍然存在一次从内核读缓冲区到套接字缓冲区的 CPU 拷贝。

### B. `sendfile`

`sendfile` 是 Linux 2.1 内核引入的一个系统调用，专门用于在两个文件描述符之间高效地传输数据。

**工作流程**：
1.  应用程序调用 `sendfile`，DMA 将数据从**磁盘**拷贝到**内核读缓冲区**。
2.  CPU 将数据从**内核读缓冲区**直接拷贝到**内核套接字缓冲区**。
3.  DMA 将数据从**内核套接字缓冲区**拷贝到**网卡**。

**开销**：
-   **3 次数据拷贝**：2 次 DMA 拷贝 + 1 次 CPU 拷贝。
-   **2 次上下文切换**。

`sendfile` 的数据传输完全在内核空间内完成，避免了数据进出用户空间，因此也减少了上下文切换次数。

### C. `sendfile` + DMA Gather Copy (真正的零拷贝)

从 Linux 2.4 内核开始，`sendfile` 得到了增强，如果网卡驱动支持 "Gather Operation"（分散/聚集操作），可以实现真正的零拷贝（从 CPU 角度看）。

**工作流程**：
1.  应用程序调用 `sendfile`，DMA 将数据从**磁盘**拷贝到**内核读缓冲区**。
2.  **没有 CPU 拷贝**。CPU 只将一个带有数据位置和长度信息的**描述符**附加到**内核套接字缓冲区**。
3.  DMA 控制器根据套接字缓冲区中的描述符，直接从**内核读缓冲区**将数据**聚集 (gather)** 起来，并拷贝到**网卡**。

**开销**：
-   **2 次数据拷贝**：2 次 DMA 拷贝，**0 次 CPU 拷贝**。
-   **2 次上下文切换**。

这是零拷贝最理想的实现方式，完全消除了 CPU 的数据搬运工作。

### D. `splice`

`splice` 是 Linux 2.6.17 引入的系统调用，它可以在两个文件描述符之间移动数据，而不需要数据在内核空间和用户空间之间进行拷贝。它不限于 `sendfile` 的文件到套接字，而是可以在两个任意文件描述符之间建立**管道 (pipe)** 来传输数据。

**工作流程 (文件到网络)**：
1.  用户空间调用 `splice`，DMA 将数据从**磁盘**读入到**内核读缓冲区**。
2.  CPU 在内核空间内建立一个管道，将内核读缓冲区和套接字缓冲区连接起来。这只是指针操作，没有数据拷贝。
3.  DMA 从管道（实际上是内核读缓冲区）中将数据拷贝到**网卡**。

**开销**：
-   **2 次数据拷贝**：2 次 DMA 拷贝，**0 次 CPU 拷贝**。
-   **2 次上下文切换**。

`splice` 更加通用，可以实现任意两个文件描述符之间的零拷贝。

## 4. 技术对比

| 技术方案                  | CPU 拷贝次数 | DMA 拷贝次数 | 上下文切换次数 | 系统调用         |
| ------------------------- | ------------ | ------------ | ---------------- | ---------------- |
| 传统 `read` + `write`     | 2 次         | 2 次         | 4 次             | `read`, `write`  |
| `mmap` + `write`          | 1 次         | 2 次         | 4 次             | `mmap`, `write`  |
| `sendfile`                | 1 次         | 2 次         | 2 次             | `sendfile`       |
| `sendfile` + DMA Gather   | **0 次**     | 2 次         | 2 次             | `sendfile`       |
| `splice`                  | **0 次**     | 2 次         | 2 次             | `splice`         |

## 5. 应用场景

零拷贝技术对于需要处理大量 I/O 的高性能应用至关重要。

-   **Kafka**：作为一个高吞吐量的消息队列，Kafka 在从磁盘读取消息并发送给消费者时，广泛使用了 `sendfile` 技术，这是其能够实现百万级 QPS 的关键之一。
-   **Nginx**：作为高性能的 Web 服务器，Nginx 在处理静态文件时，会开启 `sendfile` 选项，以极高的效率将文件内容发送给客户端。
-   **RocketMQ**：同样在消息传递中使用了 `mmap` 技术来提高文件读写效率。
-   **Netty**：Java 的高性能网络框架，也提供了对零拷贝的支持。

## 坑

- **零拷贝不是免费的**：它省的是 CPU 拷贝，但仍需 NIC 支持 scatter-gather DMA、内核版本够新、文件页在页缓存里；第一次冷读文件时 `sendfile` 走的还是 page cache miss，并不会比 read+write 快。
- **`sendfile` 只能 fd→socket 或 fd→fd**：源必须是文件描述符（文件/pipe），不能直接把用户态 buffer（`malloc` 出来的数据）发出去；要发送应用层组装的数据还得先写临时文件或用 `splice` 绕。
- **`mmap` 有页缓存抖动风险**：大文件 mmap 后随机访问会触发 page fault 和 page cache 回收，内存压力下反而比 read 慢；且 mmap 写入要等 msync 才落盘，崩溃会丢数据。
- **DPDK/SRDMA 才是真正的"用户态零拷贝"**：Linux `sendfile`/`splice` 在内核态省了一次拷贝，但 buffer 仍在内核页缓存；要做到网卡和用户态 buffer 直接 DMA 直通，得用 DPDK、RDMA、io_uring + registered buffer。
- **混淆"零拷贝"语义**：Netty/Java NIO 的零拷贝是用户态 buffer 合并、不是内核态的零拷贝；Kafka 的零拷贝指的是 `sendfile`，不是"完全没有数据移动"——DMA 拷贝和上下文切换依然存在。
