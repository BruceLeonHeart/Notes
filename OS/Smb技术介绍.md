# SMB协议个人整理笔记（纯Markdown，直接复制使用）
## 一、核心概述
SMB（Server Message Block，服务器消息块）：**局域网C/S文件资源共享协议**，微软主导，Windows原生内置
- CIFS：是SMB1.0的旧名称，二者同源
- 核心用途：局域网文件、打印机共享，映射网络驱动器

## 二、端口区分
1. SMB2.0/3.x（现行全部主流系统）：仅占用 **TCP 445**，无NetBIOS依赖，Win7及以上默认使用
2. SMB1.0（淘汰废弃）：占用 **TCP 139+445**，依赖NetBIOS，仅XP/2003使用
> 硬性要求：所有设备**永久关闭SMB1.0**，永恒之塔勒索病毒利用该版本漏洞

## 三、版本迭代对比
|版本|适配系统|核心特点|使用建议|
| ---- | ---- | ---- | ---- |
|SMB1.0(CIFS)|XP、Server2003|报文臃肿、无加密、高危漏洞多|**强制关闭，禁止启用**|
|SMB2.0/2.1|Win7、Server2008|请求合并、低延迟、断线重连|仅老旧内网兼容使用|
|SMB3.0|Win8/10、Server2012|传输加密、多通道带宽聚合|企业内网标准版本|
|SMB3.1.1|Win11、Server2016+|AES256加密、防中间人、SMB over QUIC外网穿透|**个人/企业首选版本**|

## 四、原生支持功能
1. 文件：局域网互访、网络驱动器映射、多人文件锁、断点续传
2. 外设：局域网共享打印机、扫描仪
3. 企业高阶：AD域权限管控、Hyper-V共享存储、SQL共享数据盘

## 五、跨操作系统使用时机（核心考点）
### 判断铁律
只要通信**一端是Windows**，优先使用SMB；两端均为类Unix系统不用SMB
### 互通明细
1. Windows ↔ Windows：SMB3.1.1，访问格式`\\IP\共享名`，无需额外软件
2. Windows ↔ Linux：Linux部署**Samba服务**；Windows直接访问，Linux使用`cifs-utils`挂载
3. Windows ↔ Mac：SMB（苹果已废弃AFP协议），Mac访问格式`smb://IP/共享名`
4. Linux ↔ Linux：使用**NFS**，性能开销更低，无需Samba
5. Mac ↔ Mac：系统默认原生SMB
6. NAS/电视/播放器 ↔ 电脑：统一用SMB，设备兼容性最强

## 六、优缺点总结
### 优点
1. Windows开箱即用，完美适配NTFS文件权限、AD域账号体系
2. 支持并发文件锁、断点续传，适配办公多人协作
3. SMB3及以上支持传输加密、报文防篡改，内网安全可靠

### 缺点
1. SMB1漏洞泛滥，公网暴露端口极易中勒索病毒
2. Linux端Samba配置繁琐，UID/GID权限容易错乱
3. 高延迟外网环境传输效率差

## 七、安全注意事项
### 禁止操作
1. 严禁公网直接放行TCP 139、445端口
2. 全网终端统一禁用SMB1.0

### SMB替代场景
1. 外网文件传输：SFTP/FTPS/WebDAV
2. Linux集群内网共享：NFS
3. 大文件增量同步：Rsync

## 八、日常排错极简总结
1. 无法访问：检查防火墙445放行、两端SMB版本协商、SMB1是否关闭
2. 权限拒绝：核对Windows账号密码、**共享权限+NTFS本地权限双层校验**
